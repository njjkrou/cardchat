## 这是什么

藏春阁是一套**可以直接运营**的 AI 角色聊天平台。用户创建或导入角色卡，和角色进行长期的角色扮演对话；
平台负责模型接入、上下文组装、长期记忆、内容安全与爱心计费，管理员在后台完成审核、配置与运营。

和「套一个聊天框」不同，这套系统真正难的部分都在服务端：

- **上下文工程**：角色卡、世界书、预设、正则脚本、引用回复、记忆块，按 token 预算拼装
- **长期记忆**：分层压缩 + 事实抽取 + 混合检索，让角色在几十轮之后还记得你
- **多租户计费**：平台 Key 与用户自带 Key 双通道，按 usage 精确结算，订阅与爱心并存
- **可运营**：审核、订单、流水、订阅、公告、平台配置，后台一应俱全

> 本仓库仅包含**前端构建产物（已混淆）**用于展示与分发，后端服务源码不公开。
> 下面的功能说明覆盖完整的前后端能力。

## 技术架构

<p align="center">
  <img src="docs/architecture.svg" alt="系统架构图" width="100%">
</p>

**技术栈**

| 层 | 选型 |
|---|---|
| 前端 | Vue 3 · TypeScript · Vite · Pinia 风格组合式状态 · SSE 流式渲染 |
| 后端 | Node.js（22/24）· Express · TypeScript |
| 数据库 | SQLite（WAL）· `node:sqlite` 驱动 · FTS5 全文检索（trigram） |
| 模型接入 | 任意 OpenAI 兼容网关，支持流式 / 非流式回退 |
| 部署 | Docker Compose（server + web 双容器）· Nginx 反向代理 |

设计上的几个取舍：

- **单进程 + SQLite**：中小规模运营下省去 Redis/MySQL 运维，WAL 模式支撑并发读写，备份就是复制一个文件
- **服务端持有模型 Key**：前端不接触任何密钥，用户可选填自己的 Key 免费使用
- **同步流式 + 异步记忆**：对话走 SSE 即时返回，摘要与事实抽取放到后台调度器，不阻塞用户

### 三、长期记忆系统（核心）

角色聊得越久，上下文越贵。这套系统把「记住什么」拆成三层，用固定的 token 预算换取尽可能长的记忆：

| 层 | 做什么 | 成本 |
|---|---|---|
| **L1 工作记忆** | 按 token 预算 + 条数上限切出最近若干条原文 | 每轮固定预算 |
| **L2 分段摘要** | 每攒够 30 条或 6000 字，后台生成一段摘要，写完永不重算 | 每 30 条一次调用 |
| **L3 事实卡** | 从摘要中抽取「身份 / 偏好 / 关系 / 事件」事实，去重合并 | 随 L2 产生 |
| **检索注入** | 用当前输入做关键词检索，命中相关往事片段 | 每轮一次本地查询 |

其他设计细节：

- **不截断就不注入**：历史本来就没超预算时，记忆块不注入，避免白花 token
- **关键词按句轮转抽取**：避免被第一句长文本吃光配额，保证「花生过敏」这类短词能被检索到
- **事实去重**：2-gram 相似度 + 最长公共子串，合并同义事实，防止「猫叫煤球」出现六遍
- **每对话独立开关**：默认开启，用户可在聊天页随时关闭
- **摘要失败不写库**：模型返回异常时跳过本轮，指针不推进，下轮重试

实测数据（真实对话）：长回复场景下 **prompt token 降低约 35%**，且角色能准确回忆起窗口之外的事实。

## 后端能力说明


**1. 认证与租户隔离**
JWT 鉴权、bcrypt 密码散列、图形验证码、限流；所有数据查询强制带 `user_id` 条件，避免越权。

**2. 模型接入层**
OpenAI 兼容协议，支持平台 Key 与用户自带 Key 双通道；流式请求失败自动降级为非流式；
对网关返回的「HTTP 200 + 错误文本」做内容级防护，避免把报错当回复写进历史。

**3. Prompt 引擎**
按顺序组装：系统提示 → 角色卡（描述/人格/示例对话）→ 世界书扫描结果 → 预设条目 → 人设 →
长期记忆块 → 最近历史 → 用户输入。支持 SillyTavern 宏（`{{char}}`、`{{user}}` 等）、
引用回复展开、token 预算裁剪。

**4. 记忆服务**
后台调度器定期扫描；分段摘要与事实抽取调用独立模型；FTS5 trigram 索引 + LIKE 回退的混合检索；
摘要、事实、检索结果按字符预算截断后注入。

**5. 计费与账本**
按 usage 精确计算爱心；`coin_ledger` 幂等；订阅用户走权益抵扣；
余额校验前置到写消息之前，避免「消息入库但没有回复」。

**6. 自动消息**
定时器扫描开启自动消息的对话，按概率与冷却时间主动发消息；同样走完整计费与记忆注入；
空回复有兜底，不会产生空消息。

**7. 内容安全**
关键词与规则审核、上传文件类型与大小校验、公开内容人工审核、举报处理。

**8. 支付**
易支付下单、签名校验、异步回调、订单状态机与对账。

**9. 管理 API**
32 个管理端点，覆盖用户、角色卡、评论、订单、流水、订阅、配置、公告、通知与预设。
